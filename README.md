# dsh-qqbot-guard · QQ 群管家

> 只做群管理：违规防护、入群审批、入群欢迎、入群答题、观察期、公告发布与管理。  
> 默认不聊天；可选的「普通用户 AI 通道」只在非信任成员 @机器人 时提供受控的轻量闲聊，管理操作一律拦截。

## 1. 这是什么

`dsh-qqbot-guard` 是一个运行在 **dsh（Node.js 宿主）** 里的 QQ 群管理插件。它只订阅群事件，做以下事情：

1. **群聊违规防护**：本地词表/正则/模糊变体/图片广告/链接/刷屏检测，命中后警告、禁言或移出。
2. **入群审批**：风险自动拒绝、关键词自动通过、黑名单自动拦截、面板手动审批。
3. **入群欢迎与观察期**：新成员欢迎语、默认 10 分钟观察期（可自定义）、可选入群答题。
4. **公告与群成员管理**：公告草稿/定时/立即发布/历史，群注册表、成员台账、禁言/解除/移出。
5. **独立局域网控制台**：不依赖 dsh 设置页，浏览器直接访问，双密码分权，支持按群覆盖、黑名单、审计导出、配置备份。
6. **可选 AI 辅助**（有总开关，默认关闭）：违规补判、入群审批、入群答题、自然语言指令解析（v1.9.0 起 AI 优先、关键词仅兜底），以及面向普通成员的受控轻量闲聊。
7. **群内运维指令**：白名单成员可查询设备/资源占用、查询 AI 接口余额，或完整重启插件服务并自动重新登录。
8. **API 余额充值（v1.15.0，可选）**：群内发「充值 50 支付宝」，插件受理后由 DSH 的 agent 用浏览器完成真实支付，二维码发回群里，成功后回执脱敏订单号（详见第 6 章，需要 BrowserSkill）。

所有能力既可以在 dsh 内置设置页使用，也可以通过独立控制台 **`http://局域网IP:8790/`** 操作。

## 2. 与原版相比有哪些改动

### 【1】 定位差异

| 维度 | 原版 `dsh-qqbot` | 本版 `dsh-qqbot-guard` |
|---|---|---|
| 定位 | 综合 QQ 机器人（AI 对话 + 多种媒体能力 + 群管理） | 以群管理为主，可选轻量 AI 辅助 |
| AI 模型 | 有，依赖 AI 会话/模型调用 | **可选，默认关闭**：违规补判、入群审批、自然语言指令解析、普通成员闲聊 |
| 聊天回复 | 有 | 可选（仅非信任成员 @机器人 时的受控闲聊） |
| 表情包 / 图片 / 语音 | 有相关模块与依赖 | 表情包/语音移除；图片仅用于可选的违规识别 |
| 群管理 | 有，但与 AI 会话深度耦合 | 保留并重写为独立事件驱动 |
| Web 面板 | 大型内置设置页 | 六页 dsh 面板 + **独立局域网控制台（双密码分权）** |
| 源码规模 | 约 910 个文件 / 15.47 MB（不含 node_modules） | **81 个文件 / 约 1.26 MB**（不含 node_modules） |
| 发布包 | 体积大，模块多 | **约 423 KB 的 zip**（含 README、CHANGELOG、LICENSE、test） |
| 原生模块 | 依赖链较重 | **零原生模块**，无需编译工具链 |
| 安装依赖 | 较重 | 仅 `@deepseek-ai/schemastery`（`@deepseek-ai/cordis` 由宿主提供） |

### 【2】 明确移除的能力

- 原版的 AI 会话、长期记忆、人格设定、工具调用与多轮上下文
- 表情包、图片生成、语音/音频处理
- 与聊天相关的重型限流与多模态处理模块
- 原版中与群管理无关的重型依赖与前端大包

> AI 能力并未全部移除：本版保留**默认关闭、可随时关停**的受控模型调用（违规补判、入群审批、入群答题、自然语言指令解析、普通成员闲聊），且全部有超时、并发与限流上限。

### 【3】 保留并重写的群管理能力

- 违规词、正则、可疑链接、刷屏检测
- 警告 / 禁言 / 移出，以及失败时的降级链
- 多次违规自动升级
- 入群申请自动/手动审批
- 入群欢迎与多变体模板
- 公告草稿、定时、立即发布、暂停、删除、历史
- 群注册表、成员台账、禁言/解除/移出
- 违规与操作审计

### 【4】 资源与稳定性优化

- **单一 WebSocket 连接**，不轮询业务事件
- **单个 30 秒公告调度器**，不为每条公告创建定时器
- 状态文件**合并写盘**（默认 5 秒），避免每条消息都写磁盘
- 成员、待审批、违规记录、审计日志都有硬上限
- 令牌缓存 + 并发单飞，避免重复取票
- QQ API 调用统一经过**熔断器**，连续失败快速降级
- 面板只在可见时低频刷新状态
- **默认不发起任何模型请求**；只有开启 AI 辅助后才按需调用，并受超时、并发上限、每群每分钟限流与结果缓存约束

## 3. 功能说明

> 完整的指令集、自然语言说法、普通用户能聊的内容与两者分界线，见 **[COMMANDS.md](./COMMANDS.md)**。

### 【1】 违规防护

在「违规防护」页配置：

- 启用/关闭防护
- 命中动作：警告 / 禁言 / 移出群聊
- 禁言时长、同一用户冷却时间
- 违规词（每行一个）
- 正则规则（每行一个）
- 可疑链接检测与域名白名单
- 刷屏检测：时间窗口 + 消息条数
- 多次违规升级：第 N 次违规后执行更重动作
- 豁免群（填群号）

执行失败时会降级：**禁言失败 → 警告**，**移出失败 → 禁言 → 警告**；不会因为某个接口失败而抛异常中断。

### 【2】 入群审批

在「入群审批」页：

- 查看本地待审批列表
- 从协议端同步待审批列表（见下方说明）
- 手动通过 / 拒绝
- 命中风险提示自动拒绝
- 关键词自动通过
- 关键词自动拒绝

> **入群申请来自 OneBot 的 `request` 事件**（v2.1.0 起不再依赖 QQ 开放平台的 `GROUP_MEMBER_EVENT`）。
> 插件收到 `request` 事件后会立刻处理并推入待审批队列；OneBot v11 **没有“主动拉取申请列表”的标准动作**，
> 因此面板上的「刷新待审批」只能列出**已经推送到的申请**，不会凭空变出新申请。
> 审批时 `set_group_add_request` 的 `sub_type` 按事件原样回传（`add` / `invite`），不会再写死成 `invite`。

### 【3】 入群欢迎

- 模板变量：`{user}`（@新成员）、`{name}`（昵称）、`{group}`（群名）
- 支持多条欢迎语变体
- 变体选择由 **种子随机** 驱动：同群、同成员、同一天固定，可复现
- 修改「随机种子盐」即可换一批欢迎语

### 【4】 公告

- 新建公告：标题（可选）+ 正文
- 保存为草稿 / 定时发布 / 创建后立即发布
- 暂停定时、删除、查看发布历史
- 发布结果按群记录成功/失败
- 定时调度器每 30 秒扫描到期公告
- **真·群公告（v1.14.0 新增）**：设置里启用 NapCat 后，新建公告可选手「真·群公告」——通过协议端 `_send_group_notice` 写进 QQ 群原生公告栏（支持置顶、需确认），发布失败自动回落到机器人消息；面板「公告」页可拉取目标群现有公告并删除（`_get_group_notice` / `_del_group_notice`）。
- **v1.16.9**：群里说「发公告 内容」时，**NapCat 可用则默认发真·群公告**（`_send_group_notice`），否则回落为机器人消息；「查看公告」优先调用 `_get_group_notice` 读群内真公告。前提：NapCat 协议端在线、机器人（QQ 账号）是群管理员/群主。

> **兼容性说明**：v2.1.0 起插件只走普通 QQ 账号（NapCat / OneBot v11）。协议端在线且机器人为群管理员/群主时，公告可发成 **QQ 原生群公告**（`_send_group_notice`）；协议端不可用或权限不足时自动回落到**普通群消息**，保证公告不丢。

### 【5】 群与成员

- 群注册表：收到群事件后自动登记，也可手动添加群号 + 名称
- 成员台账：记录机器人见过的成员（入群申请、群消息）
- 成员搜索：昵称 / QQ 号
- 禁言 / 解除禁言 / 移出群聊
- **NapCat 成员目录（v1.7.0 新增，v2.1.0 起为唯一连接方式）**：插件通过 OneBot v11 拉取完整花名册。默认已启用（`napcat.enabled = true`，地址默认 `ws://127.0.0.1:3001`），启动时连不上会自动扫描协议端配置并回填端口 / token，也可以在「设置 → NapCat 成员目录」点「自动探测」手动触发。插件会调用 `get_group_list` 与 `get_group_member_list`（默认带 `no_cache: true`，绕过协议端缓存、直接向服务器拉取），把完整花名册和真实 QQ 号合并进成员列表：
  - v2.1.0 起群标识本身就是 QQ 群号，默认**恒等映射**（v2.2.6 修正，此前还要按群名去猜，猜不到就同步不了）；历史遗留的 32 位 openid 群仍可在「手动群映射」里一行填 `旧群 openid = QQ 群号`
  - 成员列表新增 QQ 号与来源（本地台账 / 协议端花名册 / 两者合并），支持按 QQ 号搜索
  - 「同步花名册」按钮可手动刷新；打开成员页时按缓存时长自动同步
  - 群内查询也受益：受信任成员问「查询‘某某’的信息」或下指令时，如果台账里没有这个人，插件会用花名册补全他的 QQ 号与入群信息并回复，而不是只回一句“找不到”
  - 只补全「看得到谁」，管理动作仍由协议端执行：台账里的 QQ 号直接用于禁言 / 移出
  - 协议端连不上时不影响原功能，面板会提示原因并自动回退到本地台账
  - 地址 / token 模板与「自动探测」的用法见「5. 安装 → NapCat 成员目录」；AI 安装提示词里也包含这一步，避免装完连不上

> v2.1.0 起插件只走 OneBot v11，`get_group_member_list` 能直接拿到**全量成员与真实 QQ 号**；协议端连不上时才退回本地台账（那时只能看到发过言的成员）。

### 【6】 独立局域网控制台（v1.1.0 新增）

插件启动后会自动拉起一个独立 HTTP 面板，默认监听 `0.0.0.0:8790`，不需要经过 dsh 设置页：

- 访问地址：`http://本机局域网IP:8790/`（控制台「总览」页会列出所有可用地址）
- **双密码分权**
  - **最高管理员**：全部权限；修改机器人级设置直接保存，不再三次确认
  - **普通管理员**：可修改全部设置；改违规词、模糊别名、欢迎语直接保存，改机器人级设置需要连续确认 3 次
  - 密码修改、配置导入、公告发布、入群审批、成员处置、群登记仍仅限最高管理员
- **首次访问时由部署方设置密码**，插件不内置任何默认密码
- 密码要求：**8–64 位，必须同时包含字母和数字**；两个角色的密码不能相同
- 登录成功后使用 HttpOnly + SameSite=Strict 会话 Cookie；写请求必须带 CSRF 校验头
- 登录失败按 IP 限流，连续失败会临时锁定
- 支持按群覆盖、黑名单管理、审计筛选/CSV 导出、配置 JSON 导出/导入
- **修改日志**：查看设置保存、密码修改、配置导入记录，包含操作者、来源 IP 与变更摘要，支持关键字筛选和 CSV 导出
- **首页设备信息**：机器人账号、插件版本、WebUI 版本、NapCat 版本（未接入时显示“未接入”）、系统版本，以及 CPU 型号 / 占用、内存占用和进程占用
- 状态轮询只在页面可见时进行

> dsh 内置设置页与独立控制台使用**同一套标签页与字段**（总览 / 违规防护 / 入群 / 公告 / 群与成员 / 黑名单 / 审计 / 修改日志 / 设置），两处读写同一份配置，改完即互相同步。

**为什么要分两个密码**

- **最高管理员**是部署方本人，改设置直接生效，避免每次都被三次确认打断。
- **普通管理员**用于协管或值班：可以改设置，但涉及机器人级设置必须连续确认 3 次，并留下修改日志和群内变更通知，降低误操作风险；最高管理员修改只在本地记录，不在群里发任何消息。
- 两个角色只靠密码区分，不需要额外账号系统；密码只保存 PBKDF2 哈希，不保存明文。

> 首次打开控制台会进入“设置密码”页，由部署方自行填写最高管理员与普通管理员密码。密码只保存 PBKDF2 哈希，源码与仓库中不包含任何默认密码或明文。
>
> 首次设置入口对局域网开放：部署完成后请立即访问并设置密码，避免同一局域网内的其他人抢先初始化。
>
> 面板走 HTTP，适合可信局域网。不要把端口直接暴露到公网；如需远程访问，请使用 VPN 或带 HTTPS 的反向代理，并设置足够强的密码。

### 【7】 机器人设置的“三次确认 + 群内通知”

**普通管理员**在控制台修改**机器人级别设置**（连接凭据、处罚动作、审批策略、观察期、答题、公告策略、按群覆盖中的非词表字段等）时：

1. 前端连续弹出 **3 次确认**；
2. 服务端同时要求 3 次挑战令牌，缺少令牌会返回 `CONFIRM_REQUIRED`；
3. 保存成功后，异步向机器人已加入的**所有群**发送变更日志；
4. 在「设置 → 变更通知对象」里填写**昵称**；QQ 号可以留空。留空时按昵称匹配：群内该昵称唯一就 @ 他；有同名成员才需要补 QQ 号，或直接从“成员列表”下拉选人（自动填入昵称与 QQ 号）。**仅普通管理员修改时才会发送群消息**；最高管理员修改不在群里发任何日志或消息，只在本地记录。昵称留空时，普通管理员修改也只发日志。

**最高管理员**不触发三次确认：保存后直接生效，**不在群里发送任何日志或消息**，只在本地修改日志中留档。

> “已加入的群”以插件登记的群为准（机器人收到过群事件或手动登记的群）。QQ 官方没有全量群列表接口；如果某个群从未产生事件，插件无法知道它。
> **v2.1.0 起成员标识就是真实 QQ 号**（不再有 openid）。通知对象只需填昵称：群内没有同名成员就会 @ 他；有同名成员时再从「成员列表」下拉选人，会自动填入昵称与 QQ 号。
> 保存前可以点「验证通知对象」：先查成员台账；台账没有记录时会提示让该成员先在群里发言。确认昵称不匹配或同名成员过多会阻止保存，暂时无法校验则只提示、不拦截。
> 群聊 @ 由协议端转成 OneBot 的 `at` 消息段（内部统一用 `<qqbot-at-user id="QQ号" />` 标记，发送前自动转换）；@全体 用 `id="all"`。协议端离线时消息发不出去，会在审计里留下 `reply-failed` 记录。

只修改违规词、模糊别名、欢迎语等“词”级别内容时，不触发三次确认和群通知。

### 【8】 v1.1.0 新增的群管理能力

- **管理员/信任成员豁免**：信任成员不触发警告/禁言/移出，同时允许使用群指令。白名单按 **QQ 号**维护（可从「群与成员」直接选人，不必手工复制）。
- **违规累计黑名单**：窗口内第 N 次违规自动踢出并加入黑名单，重启后仍保留
- **模糊变体匹配**：识别拆字、空格、符号与常见谐音（如 `傻 b`、`shabi`），ASCII 短词带词边界，避免误伤普通英文
- **图片/卡片检测**：图片 + 广告关键词判定为广告；观察期内图片/链接可直接按观察期动作处理；卡片/名片消息可识别
- **群内管理员指令**：`/warn @成员 原因`、`/mute 10m @成员`、`/kick @成员`、`/rule`、`/help`、`/设备`、`/重启`
- **新成员观察期**：默认 **10 分钟**，可按群覆盖为任意分钟数（0 = 不启用）
- **入群答题**：入群后在群里提问，答对才通过；支持超时、最多答错次数、失败动作
- **按群独立配置**：每个群可单独覆盖违规动作、禁言时长、词表、观察期、欢迎语
- **配置导入/导出**：备份词表、按群配置、公告、黑名单；默认不导出 NapCat token

### 【9】 AI 辅助审核（v1.2.0 新增，v1.3.0 增强，可选）

本地词表/正则拦不住的花样辱骂、软广告，可以再交给模型判一次。默认关闭，开启后：

- **两种接入**
  - **DSH 当前会话模型**：直接复用 dsh 已配置的默认模型（`ctx.llm` + `agentDefaultModel`），不需要另填密钥
  - **OpenAI 兼容接口**：DeepSeek、豆包（火山方舟）、通义千问（阿里百炼）、智谱 GLM、小米 MiMo，以及本地 Ollama / LM Studio / vLLM
- **只处理本地规则没命中的消息**；命中后按你配置的动作执行（警告 / 禁言 / 移出），模型不直接决定处罚
- **图片审核（v1.3.0）**：开启后会把消息里的图片一起送给支持视觉的模型，能识别图片里的辱骂文字、广告、二维码和引流信息。默认最多 **3 张**、单张 **≤ 3MB**，可在面板自行调整（1–5 张 / 1–8MB）。DSH 模式需要宿主的附件服务；OpenAI 兼容模式直接用 data URI 传给视觉模型
- **两种模式**
  - **识别即处置**（默认）：置信度达到阈值就按动作处理
  - **只记录建议**：只写审计，不处置，适合先观察
- **入群审批（AI 全权）**：默认由 AI 决定通过 / 拒绝；黑名单和风险提示的拒绝保留；AI 不确定或置信度不足会转人工
- **审批时段**：全天 24 小时 / 仅白天 / 仅晚上 / 群活跃时（最近 N 分钟有消息），按北京时间，可在面板调整起止小时
- **AI 入群验证**：**日常常识题为主、算术题为辅**；算术题会用本地计算校正答案；答对通过，超时或答错次数用尽按配置踢出
  - 日常题连续答错 **2 次**会自动换成算术题（阈值可配）
  - 成员输入 **“换题 / 太难了 / 不会”** 可直接换一道更简单的题（有次数上限，防止无限拖延）
  - 提问文案自带提示：`请回答该问题以便验证是否为人机【若不会或不清楚答案是否正确时可输入“换题”】`
  - 本地比对不一致时可再让 AI 判卷（同义、错别字都能通过）
- **失败保护**：超时（默认 8 秒）、熔断、并发上限、每群每分钟限流、结果缓存；断网、输出不合规或置信度不足时**自动回退本地规则**，不会误踢
- **省额度**：同一条消息 10 分钟内只判一次；短消息不调用；入群申请按 QQ 号 + 验证信息缓存；AI 出题失败会回退本地题库
- **输出严格校验**：模型必须输出 `{"verdict":"ok|abuse|ad|spam|other","confidence":0.0,"reason":"..."}`；不合格重试一次，仍失败则回退
- 面板「设置 → AI 辅助审核」里有「测试当前模型」，用一条示例广告消息试跑（使用已保存的配置）

> AI 判定属于外部服务，无法保证 100% 准确；重要群建议先用“只记录建议”跑一段时间，看审计里的 `ai-suggest` 记录，再切到自动处置。
> 提示词只包含群名、发送者昵称、截断后的消息文本（最多 800 字）以及消息图片，不会上传成员 QQ 号、群号或历史记录。
> 图片审核需要模型支持视觉（例如 qwen-vl、glm-4v、doubao-vision、MiMo-VL 等）；纯文本模型请关闭图片分析。

### 【10】 受信任成员的自然语言指令（v1.4.0 新增，v1.9.0 改为 AI 优先）

被加入「违规防护 → 信任成员」的成员，在群里 **@机器人** 后可以直接用自然语言下指令：

- `@机器人 帮我看看群里有多少人？`
- `@机器人 把“某某”踢出群聊！并拉入黑名单！`
- `@机器人 禁言“某某”10分钟`
- `@机器人 解除“某某”的禁言`
- `@机器人 警告“某某”` / `@机器人 查询“某某”的信息`
- `@机器人 @张三 让他安静10分钟`（直接 @ 目标，最准确）

规则：

- **只对信任成员生效**；普通成员 @机器人 不会触发这些操作
- **先问 AI（v1.9.0 起）**：所有自然语言指令都先交给 AI 判断，关键词不再抢先执行，避免“说得明显却被旧规则截胡”
- **关键词只兜底**：AI 未启用、超时或调用失败时，才用少量保留的快捷关键词（最多 15 个，默认 8 个：列出群成员 / 禁言 / 解禁 / 全体禁言 / 解除全体禁言 / 踢人 / 查人数 / 警告）执行，尽量不让指令白说
- **AI 失败时全体禁言不被误判（v1.14.0 修复）**：说“开启全员禁言 / 22:30 全体禁言”等带“全体/全员/全部人”强信号的指令，即使 AI 超时、且关键词表把“全员禁言”当普通“禁言”，也会正确执行全体禁言而不是禁言个别人
- **自动重排关键词**：默认每 3 周（可改，最多 10 周）或最近 7 天用满 100 次（可改）时，按你最近常用的动作重排关键词并 **@ 提醒对象**；提醒对象可在「自然语言决策」里指定；关键词最多保存 15 条
- **关键词疑似问错时会纠正**：说“列出入群审批通过关键词”会直接列出**入群审批通过关键词**（自动通过开关 + 词表），不会再甩一串违规词；说“查看违规词”才列违规词
- **入群审批关键词也能改**：`添加入群通过关键词 学生`、`删除入群通过关键词 学生`、`查看入群审批拒绝关键词`、`开启入群自动通过`
- **所有指令都能自然语言触发**：踢人/禁言/警告/查人数/查成员，以及 `/设备`、`/余额`、`/重启`、`/help`、`/rule`
- **英文直接说，由 AI 解析（v1.11.0 新增）**：`kick John`、`mute Bob 10 minutes`、`how many members`、`check cpu usage`、`list all members`、`add keyword spam`、`disable auto moderation` 都交给 AI 理解；AI 未启用 / 超时 / 出错时**直接回复“英文指令需要 AI”**，不会用本地规则去猜
- **精确指标不夹带无关信息（v1.11.0 新增）**：说“查看 CPU 占用率”只回 CPU 占用率一行；说“查看内存占用率”只回内存占用率一行；只有说“设备信息 / 设备状态”才回完整设备信息
- **全体禁言 / 定时禁言（v1.13.0 新增，v2.2.6 调整）**：`全体禁言`、`解除全体禁言`、`22:30 全体禁言`、`每天 23:00 全体禁言`、`明天 9 点禁言“某某” 1 小时`、`3 分钟后全员禁言`、`查看定时任务`、`取消定时任务 1`；到点自动执行，计划写入 state.json，重启不丢。**v2.2.6 起优先用协议端群级开关（`set_group_whole_ban`），一次生效、覆盖新成员；协议端不支持时才逐人禁言。**
- **错别字 / 谐音 / 拼音交给 AI（v1.13.1 调整）**：`拳体禁盐`→全体禁言、`把张三踢乐`→踢人、`给张三解近`→解禁、`jin yan li si 10 fen zhong`→禁言 10 分钟，**全部由 AI 理解，本地不维护容错表**；AI 未启用/超时/出错时不会去猜错别字，只走保留的快捷关键词（或明确提示换个说法）
- **AI 总开关（v1.12.0 新增）**：设置里一键关闭后所有 AI 功能（违规补判、入群审批、入群答题、自然语言指令解析、闲聊、回复润色）全部失效，模型一次都不调用，全部走本地规则；重新打开即恢复，不用逐项改
- **回复优先由 AI 生成（v1.11.0 新增）**：执行结果先交给 AI 改写成一句自然的群聊回复；AI 超时、报错或未启用时原样发送本地结果，不会因此丢掉指令结果
- **目标成员优先取被 @ 的那个人的 QQ 号**，改名、重名都不会误伤；**@机器人 自身不会被当成目标**
- **消息里直接写 QQ 号也能定位**（例如“禁言 1 分钟, 123456789”），时长和纯数字不会被误当成昵称
- **省略目标可以接上下文**：上一条刚查询/操作过某位成员，接着发“禁言 1 分钟”会默认沿用他（10 分钟内有效）
- **昵称必须精确命中台账**：同名或只差几个字都不会猜人，只回复候选成员让你确认
- **免 @ 续聊**：同一成员 @ 过一次后，默认 60 秒内继续说话不必重复 @（面板可改，填 0 关闭）
- **无论成功还是失败都会 @ 你回复**，并说明原因（找不到人、同名、不能操作自己、接口失败等）
- 查询人数会同时返回协议端群人数与本地台账记录数
- 所有自然语言操作都会写入审计（`natural-kick` / `natural-mute` 等）

不止成员处置：**插件里能查、能改的东西，都可以一句话完成**（同样只对信任成员 / 白名单生效，先说“管理功能”可查看完整清单）。能直接说：

- **查名单**：`列出所有群成员名单`、`看看花名册`（有 NapCat 成员目录时带 QQ 号，并标出还没发过言的成员；同一个人只出现一次，并标注 `[群主]` `[管理员]` `[白名单]` `[信任]` `[机器人]`）
- **查黑名单 / 白名单 / 信任成员 / 违规词**：`查看黑名单`、`有哪些白名单成员`、`看看信任成员`、`查看违规词`
- **查入群审批关键词**：`列出入群审批通过关键词`、`查看入群审批拒绝关键词`（和违规词是两套，不会互相混）

- **查待办**：`有哪些待审批`、`看看公告列表`、`同步一下花名册`

- **改黑/白名单**：`把“某某”加入黑名单`、`把“某某”移出黑名单`、`把“某某”加入白名单`、`把“某某”设为信任成员`
- **改审核参数**：`默认禁言时长设为 10 分钟`、`违规处置改为禁言`（警告/禁言/移出/删除消息）

英文同样可用：`list all members`、`show blacklist`、`add keyword spam`、`check memory usage`、`mute Bob 10 minutes`、`disable auto moderation`。英文**只由 AI 解析**（没有任何本地英文词表文件）；AI 不可用时插件会明确回复“英文指令只通过 AI 解析”，让你改用中文或先启用 AI，绝不瞎猜动作。

#### 全体禁言与定时任务（v1.13.0 新增，v2.2.6 明确为“群级开关优先”）

v2.1.0 起只走普通 QQ 账号，全员禁言**优先用协议端原生群级开关**：

- **首选：协议端群级开关** —— `set_group_whole_ban`，一次调用立即对全群生效，新进群成员同样受限，不逐个成员操作、也不受人数上限影响。
  回执会明确写成「协议端群级开关」，**不会把台账人数当成“禁言成功人数”**回报（v2.2.6 修正）。
- **兜底：逐人禁言** —— 协议端不提供 `set_group_whole_ban` 时，退回按台账逐个禁言（群主 / 管理员 / 机器人自动跳过，单次最多 200 人）。这条路径才是“不会出现全员禁言横幅、新成员不受影响”的情况。
- `lib/whole-ban.js` 统一实现，自然语言、面板、定时任务共用同一套逻辑；返回值带 `groupLevel` 标记，回执与审计据此区分两种路径。
- **定时禁言**：`lib/scheduler.js` 每 20 秒检查排期，到点由插件自己执行，重启不丢；**控制权完全在插件里**（不依赖任何外部调度器）：

  | 说法 | 效果 |
  |---|---|
  | `22:30 全体禁言` | 今天 22:30 一次 |
  | `每天 23:00 全体禁言` | 每天 23:00（daily） |
  | `明天 9 点禁言“某某” 1 小时` | 定时禁言成员，带 QQ 号 |
  | `3 分钟后全员禁言`、`半小时后解除全员禁言` | 相对时间 |
  | `查看定时任务` / `取消定时任务 1` | 查看 / 取消（序号会先解析成任务 id，最终只按 id 精确删除） |

- **重复设置 = 修改（v1.14.1）**：同群同动作再次设置时直接替换旧任务（`22:30 全体禁言` → 再说 `23:00 全体禁言`，排期改为 23:00），不会排出两条；不同动作 / 不同重复方式 / 不同群的任务各自独立。
- 面板「群与成员 → 全体禁言与定时任务」有同样的按钮与列表：立即全员禁言 / 解除、时间 + 动作 + 每天重复 → 添加、列表内取消。
- **取消只按 id 精确删除（v2.2.6 修正）**：旧实现把传入值同时拿去比 `time`（`"22:30"`）和 `at`（时间戳），
  传空 id 会**删掉所有一次性任务**、传 `"22:30"` 会**跨群误删**同时间任务。现在只按 id 精确匹配，空 id 直接拒绝并提示先查看列表。
- 到点执行结果写入审计（`schedule-whole-ban` / `schedule-mute` …）；失败会记 `schedule-failed`。

#### API 余额充值（v1.15.0 新增，插件 ⇄ agent 协作）

受信任成员在群里 @机器人 即可发起**真实充值**，插件负责受理与回执，浏览器操作交给 DSH 的 agent（BrowserSkill）：

1. 用户说「充值 50 支付宝」或「充值 100 元 微信」；
2. 插件解析金额与支付方式，写入 `<数据目录>/recharge/req-<id>.json`，并在**插件专用工作区**（`<数据目录>/recharge-workspace`）里**为该任务新建一个独立会话**（不复用旧会话，避免上下文串任务），用 `agent.followup()` 投递请求；任务结束后会话自动销毁（同时最多 3 个）；
3. agent 用浏览器打开用户已登录的模型充值页（默认 `platform.deepseek.com/top_up`），选择金额与支付方式、点「去支付」，把二维码截图写到 `<数据目录>/recharge/qr-<id>.png`；
4. 插件把二维码用官方富媒体接口发到群里（`msg_type=7`），用户扫码支付；
5. agent 等待支付结果（最多 2 分钟），成功后读账单页订单号与余额，写 `res-<id>.json`；
6. 插件回执：「充值成功：50 元（支付宝），订单号 `AB*****HIJ`，当前余额 …」——**订单号中间 5 位用 `*` 脱敏**；失败/超时回执原因。

前提：DSH 宿主已安装 BrowserSkill 插件与浏览器扩展，且浏览器里已登录对应模型平台账号。充值请求记录写入 `state.json`（最多 300 条），二维码文件发送成功后自动删除。

> 完整的安装与配置步骤（bsk CLI、浏览器扩展、DSH 插件与连接、排错）见 **[第 6 章：API 余额充值](#6-api-余额充值v1150可选)**。

#### 关键词与自动重排（v1.9.0 新增）

关键词不是主路径，只是“AI 抽风时别让指令白说”的保险：

- 默认 8 个（列出群成员 / 禁言 / 解禁 / 全体禁言 / 解除全体禁言 / 踢人 / 查人数 / 警告），最多 15 个，可在「设置 → 自然语言决策」里改成 `说法 = 动作`
- 动作名就是「管理功能」里列出的那套（`list-members`、`mute`、`add-keyword`、`toggle`…）
- 到重排周期（默认 3 周、最多 10 周）或最近 7 天自然语言用量达到阈值（默认 100 次）时，插件按最近常用动作生成新关键词，并 @ 提醒对象（留空则 @ 第一个信任成员）
- 这条通知只发一次，记录在审计的 `natural-keywords-review` 里

> 通知对象、信任成员、黑名单、群指令白名单等所有需要选成员的地方，都支持直接搜索昵称 / QQ 号，不需要手动复制。

### 【11】 界面语言与首次部署（v1.10.0 新增）

- 默认 **简体中文**，其次 English；首次部署**必须先选语言**——未选择前 QQ 服务不会启动，密码设置与主界面也会被拦住（服务端强制，直接调接口同样绕不过）。
- 老用户升级不会卡住：检测到已有配置或已有群/成员数据时自动视为简体中文，之后可在「设置 → 界面语言」随时切换。
- 选语言是最简单粗暴的方式：**直接替换语言包文件**即可，插件目录 `locale/` 下的 `zh.json` / `en.json` 想怎么改就怎么改。
- 通过 AI 安装时，AI 应主动询问语言选择；**30 秒不回复默认简体中文**。

### 【13】 群内闲聊与表情包（v1.13.0 优化）

普通用户 AI 通道（非信任成员 @机器人）本来就只做受控闲聊；这一版把它变得更像「人」：

- **句末 emoji**：回复末尾按概率（默认 60%）补一个 emoji，已有 emoji 不重复；emoji 池可在「设置 → 普通用户 AI 通道 → 兜底 emoji」改成逗号分隔的列表。
- **表情包图片**：在「表情包图片」里每行填一个图片 URL，闲聊回复会按概率（默认 30%）额外通过 NapCat 发一张图；NapCat 不可用或发送失败时只记审计 `guest-sticker-failed`，文字回复照常。
- 不影响安全边界：越权拦截、限流、冷却、长度上限全部仍在 AI 调用之前生效。

### 【12】 群内运维指令（v1.5.5 新增）

白名单成员 **@机器人** 后可直接查询设备或重启插件服务。两条指令都不受「启用指令」开关限制（`commands.enabled` 关闭也能用），且可在**免 @ 续聊窗口**内直接使用；但**只认白名单**：

- `/设备`：设备名、操作系统、CPU 型号与占用率、内存占用、插件版本、Node 版本、插件与系统运行时长
  - 也支持 `/device`、`/status`、`/状态`
- `/余额`：查询 AI 接口余额/额度（`/api余额`、`/api`、`/API`、`/额度`、`/quota` 均可）
  - 直接请求服务商，不消耗 token；结果缓存 60 秒
  - 内置适配 DeepSeek、Moonshot(Kimi)、SiliconFlow、OpenRouter；其它服务商按常见路径试探
  - DSH 模式由宿主计费，没有公开余额接口，会明确提示
- `/重启`：**完整重启插件运行时**（依次断开 QQ、控制面板、数据层与 AI，再从磁盘重新加载、重启面板、重连 QQ），完成后自动重新登录
  - 也支持 `/restart`、`/reload`、`/重载`；确认别名 `/确认`、`/confirm`、`/yes`、`/y`
  - **默认需要二次确认**：第一次只回复确认提示，30 秒内再发一次才执行；确认期间发其它指令会自动撤销
  - 重启完成后回到发起群 **@ 发起人回复“插件服务已完整重启成功（QQ、控制面板、数据均已重新加载）”**；任一项失败会明确说明原因，不会静默无反馈
  - 不真的结束 dsh 宿主进程（否则插件与宿主一起退出，无法回报结果），做的是运行时级完整重建

> 白名单 = 「设置 → 群内管理员指令 → 允许使用的成员」+ 「违规防护 → 信任成员」（均按 QQ 号）。两种指令都会写入审计（`device` / `restart`）。

### 【14】普通 QQ 账号管理（NapCat 模式，v2.1.0 起为唯一连接方式）

> **v2.1.0 重大变更**：官方 QQBot（AppID / AppSecret）连接已**彻底移除**，插件只通过普通 QQ 账号（NapCat / OneBot v11）工作；设置里不再有 AppID/AppSecret 字段。旧配置文件里的这两个键会被忽略。

用**普通 QQ 账号**（NapCat / OneBot v11 协议端）管理群，限制少很多：

| 能力 | 普通 QQ 账号（NapCat） |
|---|---|
| 收群消息 | **全量群消息**（可做入群答题、刷屏检测等） |
| 成员列表 | `get_group_member_list` 直接读 |
| 禁言 / 踢人 | QQ 号直接操作 |
| 全员禁言 | 原生 `set_group_whole_ban` |
| 群公告 | 原生 `_send_group_notice`（置顶 / 需确认） |

**配置**（设置 → NapCat）：

```jsonc
{
  "napcat": {
    "enabled": true,
    "wsUrl": "ws://127.0.0.1:3001",      // NapCat 的 WS 地址
    "token": ""                           // 若 NapCat 设了 access_token 就填
  }
}
```

前提条件：

1. 本机/同网段运行 NapCat（或其它 OneBot v11 实现），开启**正向 WebSocket**；
2. 用它登录**在群里是管理员/群主**的 QQ 账号（禁言、踢人、发公告都需要权限）；
3. **该 QQ 号不能同时在其它 QQ 客户端登录**——QQ 同一账号只允许一个在线会话，否则 NapCat 会报“当前账号已登录，无法重复登录”且 WS 不会启动；
4. 保存设置后插件自动重连。

> **QQ 没开也能用（v2.2.0）**：设置 → NapCat 打开「协议端自动启动」，并填「协议端启动命令」——WS 地址探测不通时，插件会自己执行该命令拉起协议端，再连接。
>
> 推荐直接指向**无头 NapCat.Shell**（自带运行时、不启动 QQ 客户端、内存约 100–200MB）：
>
> ```text
> C:\napcat\napcat.bat -q <QQ号>
> ```
>
> 也可以填计划任务（如 `schtasks /run /TN "NapCat QQ Bot"`）。这样 QQ 客户端可以完全关闭甚至卸载，插件仍能正常收发消息。
>
> 想换其它 OneBot v11 后端（Lagrange 等）只需把 `wsUrl` 指向它的 WebSocket 服务；注意 Lagrange 需要自备签名服务器。

> **数据说明**：不会删除任何本地文件。v2.1.0 起群/成员标识就是 QQ 号/群号；旧版留下的 openid 台账会保留但不再对应，新群按 QQ 号重新登记；全局设置沿用。

## 4. 兼容性

### 【1】 兼容矩阵

| 平台 | 结论 | 条件 / 说明 |
|---|---|---|
| Windows 10 / 11 x64 | 支持 | Node ≥ 24.9.0 + dsh |
| Windows Server 2016+ | 支持 | 同上 |
| Windows 10 LTSC / 精简版 | 有条件支持 | Node 与 dsh 能启动即可；不要移除 UCRT、Winsock、DNS、防火墙出站 443 |
| Windows arm64 | 有条件支持 | Node 24 对 Windows arm64 为 Tier 2 |
| Windows 7 / 8 / 8.1 | 不支持 | Node 24 官方不支持，dsh 无法启动 |
| Ubuntu 20.04+ / Debian 10+ / RHEL 8+ | 支持 | 内核 ≥ 4.18、glibc ≥ 2.28 |
| CentOS 7 / glibc < 2.28 | 不支持 | 官方 Node 24 二进制无法运行 |
| Alpine / musl | 有条件支持 | Node 官方列为 Experimental |
| macOS 13.5+ | 支持 | Node 24 要求 Darwin 22.6+ |
| iOS / iPadOS | 不能作为宿主 | 只能用 Safari 打开部署在电脑/服务器上的 dsh 面板 |
| Android / Termux | 实验性 | 可尝试，但不适合 24×7 运行，官方不支持 |

### 【2】 为什么有这些边界

1. **dsh 0.2.2 的 `engines` 要求 Node ≥ 24.9.0**，这是硬门槛。
2. Node 24 官方支持范围：
   - Windows 10 / Server 2016+（x64 为 Tier 1，arm64 为 Tier 2）
   - macOS 13.5+（Darwin 22.6+）
   - Linux 内核 ≥ 4.18、glibc ≥ 2.28
   - Alpine/musl 为 Experimental
3. **本插件零原生模块**，不需要 Python、VS Build Tools、node-gyp，也没有 `.node`/`.dll`/`.so` 文件。精简系统上常见的失败点是 Node 或 dsh 自带原生预编译包缺少 UCRT/VC++ 运行库，而不是本插件。

### 【3】 Windows 精简版建议

1. 不要移除 **UCRT、Winsock、DNS Client、防火墙出站 443**。
2. 如果 dsh 报原生模块加载失败，安装 **Microsoft Visual C++ 2015–2022 Redistributable (x64)**。
3. 数据目录不要放在 `Program Files`，默认在 `~/.dsh/qqbot-guard/...` 即可。
4. 部署后先运行 `npm run doctor`，红色必检项未解决前不要上线。
5. 控制台中文乱码不影响功能；可执行 `chcp 65001` 切到 UTF-8。

### 【4】 兼容性自检

插件启动时会自动检查：

- Node 版本
- 操作系统 / CPU 架构
- Windows UCRT
- Linux glibc / 内核
- macOS Darwin
- 全局 `fetch` / `AbortSignal.timeout`
- 数据目录可写
- dsh Web 服务是否就绪

手动运行完整体检：

```bash
npm run doctor
```

体检还会检查：

- 6 个核心模块能否加载、全局 WebSocket 是否可用、配置 Schema 依赖能否加载
- 依赖里是否存在原生模块
- 协议端 WebSocket 端口与 AI 接口 origin 是否可达（按当前配置动态探测；未配置时跳过，不再误报“网络不可达”）

面板「设置 → 兼容性自检」也会展示同样的结果。

> 测试边界：本版在 Windows 10/11 x64 + Node 26.10 上完成 281 项单测与交付自检；代码中没有平台专用分支，但未在真实 Linux/macOS 内核上运行自动化测试。建议在目标机器上运行 `npm run doctor` 和 `npm test`。

#### NapCat 成员目录（看到全部成员与 QQ 号）

v2.1.0 起插件只走 OneBot v11，`get_group_member_list`（带 `no_cache: true`）能直接拉取**完整花名册与真实 QQ 号**。首次同步时如果本地台账还是空的，插件会自动用协议端 `get_group_list` 返回的群补齐目标群（v2.2.6 修正，此前新装点「同步花名册」恒显示 0 个群）。

**这一项目前默认开启**：`napcat.enabled = true`，地址默认 `ws://127.0.0.1:3001`，启动时如果连不上会自动探测一次。通常你什么都不用填，只需要在设置页点一下「测试连接」。

如果自动探测不到，按下面模板手动填：

| 参数 | 常见值 | 去哪里找 |
|---|---|---|
| WebSocket 地址 | `ws://127.0.0.1:3001`（NapCat）<br>`ws://127.0.0.1:3000`（LLOneBot）<br>`ws://127.0.0.1:6700`（OneBot v11 默认） | 协议端配置的 `onebot11_<登录QQ>.json` → `websocketServers[].port` |
| Token | 留空（未开鉴权）或配置里的原值 | 同一个文件 → `websocketServers[].token` |
| 群映射（可选） | 每行 `群号 = QQ 群号`<br>例：`123456789 = 123456789` | v2.1.0 起群号即 QQ 群号，**通常无需填写**（恒等映射）；只有历史遗留的 openid 群才需要 |

操作步骤：

1. 打开「设置 → QQ 群管家 → NapCat 成员目录」。
2. 点 **自动探测**：插件会扫描 `~/napcat/napcat/config`、`C:\napcat\napcat\config`、`~/NapCat/config`、`~/LLOneBot/data/config` 等目录里的 `onebot11*.json`，逐个试连，找到就自动回填地址与 token。
3. 点 **测试连接**，看到「已连接：昵称（QQ），协议端可见 N 个群」即可。
4. 打开「群与成员」页，点 **同步花名册**；成员列表会出现 QQ 号、入群时间、角色，来源列会标注「官方+NapCat」或「NapCat 花名册」。
5. 按 QQ 号禁言 / 移出：直接点该成员对应的按钮即可，全部走协议端执行。

> 没装协议端时插件无法工作（v2.1.0 起连接只走 OneBot v11）；若只是想关掉花名册同步、只保留本地台账，把「启用成员目录」取消勾选即可。

1. 启动 dsh（插件会自动监听 `0.0.0.0:8790`）。
2. 在电脑/手机浏览器打开 `http://<运行 dsh 的机器局域网 IP>:8790/`。
3. 首次访问会进入“设置密码”页：分别设置最高管理员密码与普通管理员密码（8–64 位，必须同时包含字母和数字，两个密码不能相同）。
4. 保存后会自动以最高管理员身份登录；之后可在「设置 → 安全」中修改密码。
5. 如果打不开：检查 8790 端口占用、系统防火墙、云服务器安全组，确认设备在同一局域网。

> 不推荐直接把 8790 暴露到公网。远程使用请走 VPN 或 HTTPS 反向代理。

## 6. API 余额充值（v1.15.0，可选）

> 这一章讲的是**真实充值**：由机器人在群里受理，DSH 里的 AI agent 用你**已登录的浏览器**完成支付页操作，插件把二维码发到群里、支付成功后回执脱敏订单号。不需要你把账号密码交给任何人。

### 【1】它解决什么问题

模型平台的充值只能在网页上点（DeepSeek 是支付宝/微信扫码，没有充值 API）。本功能把这个网页操作交给 DSH 的 agent：插件负责解析指令、发二维码、回执结果；浏览器操作由 [BrowserSkill](https://github.com/Tencent/BrowserSkill) 驱动你本机已登录的浏览器完成。

### 【2】工作原理（插件 ⇄ agent 协作）

```
群成员 @机器人「充值 50 支付宝」
        │
        ▼
插件 lib/recharge.js：解析金额/支付方式 → 写入 <数据目录>/recharge/req-<id>.json
        │  并在专用工作区（recharge-workspace）为本次任务新建独立会话
        │  （不复用、结束即销毁），再用 agent.followup() 投递请求
        ▼
agent（BrowserSkill）：打开 platform.deepseek.com/top_up
        → 选金额 50 元 + 支付宝 → 点「去支付」
        → 二维码截图写到 <数据目录>/recharge/qr-<id>.png
        ▼
插件轮询目录：发现二维码 → 官方富媒体上传（/v2/groups/{gid}/files）
        → msg_type=7 发到群里 → 删除本地二维码文件
        ▼
用户扫码付款（3 分钟内；超时先问是否继续，可再延 2 分钟）
        ▼
agent：轮询支付结果 → 成功后打开账单页读订单号/余额
        → 写 <数据目录>/recharge/res-<id>.json
        ▼
插件：回执「充值成功：50 元（支付宝），订单号 AB*****HIJ，当前余额 …」
```

| 组件 | 职责 |
|---|---|
| `lib/recharge.js` | 指令解析、请求落盘、订单号脱敏、目录扫描 |
| `lib/natural.js` | 识别「充值 50 支付宝」，缺金额/方式时追问 |
| `lib/ai.js` | AI 解析白名单新增 `recharge`（amount/method 字段） |
| `lib/qq-api.js` | `uploadGroupImage()` 官方图片上传、`sendGroupMedia()` 发富媒体消息 |
| `index.js` | `agent/created` 记录会话、`agent.followup()` 唤醒、1.5s 轮询二维码/结果目录 |

> **模型从哪来（v1.16.0）**：插件在 DSH 注册 provider `qqg-deepseek`，用 `lib/llm-bridge.js` 把 DSH 的模型请求（文本/推理/工具调用流式）转发到「设置 → AI 辅助审核」里配置的 `baseUrl` / `apiKey` / `model`。因此专用会话消耗的是**插件自己的 API 额度**，不需要修改 DSH 配置文件，也不依赖 DSH 默认模型；只有插件 API 未配置时才回退 DSH 默认模型。`bridge.log` 会记录 `llm bridge registered: qqg-deepseek (<baseUrl>)`。
>
> 中转的请求超时是**独立的 300 秒**（v1.16.7），不跟随「AI 辅助审核」里的 `ai.timeoutMs`（那项只用于轻量意图解析，默认很短）；每次中转会在 `bridge.log` 里记录 `llm 中转请求 …` / `llm 中转完成 …s` / 失败原因。

> **充值任务提示词（动态生成）**：每次充值由插件按当前请求**实时填入**以下字段——请求 ID、群、用户、金额、支付方式、请求文件、工作区、二维码/结果输出路径。文档里的数值只是示例（`<…>` 示意），实际以本次请求数据为准，插件不会使用固定值。提示词要求 agent「勿向用户转述、不暴露路径与 QQ 号」，失败码限定为 `BSK_CLI_MISSING` / `BROWSER_NOT_CONNECTED` / `LOGIN_REQUIRED` / `PAGE_CHANGED` / `PAYMENT_TIMEOUT` / `UNKNOWN`。

**提示词完整示例**（所有 `<…>` 都由插件按本次请求实时替换，不是固定值）：

```text
【插件充值任务】dsh-qqbot-guard 内部执行指令，勿向用户转述。

## 请求信息
- 以下均为本次请求的实际数据（由插件按当前命令实时填入，不是固定值）：
- 请求ID：<本次请求ID>
- 群：<本次群号>
- 用户：<本次用户昵称>（QQ 号 <本次用户 QQ 号>）
- 金额：<本次金额> 元
- 支付方式：<本次支付方式>
- 请求文件：<本次数据目录>/recharge/req-<本次请求ID>.json
- 工作区：<本次数据目录>/recharge-workspace
- 二维码输出：<本次数据目录>/recharge/qr-<本次请求ID>.png
- 结果输出：<本次数据目录>/recharge/res-<本次请求ID>.json

## 操作步骤
0. 读取请求文件确认上述信息；若 bsk_* 工具不可用，先调用 skill 加载 "browser-skill"；加载后仍不可用 → BSK_CLI_MISSING。
1. 确保浏览器可用：先用系统命令打开「默认浏览器」（Windows 示例：`start msedge` / `start chrome` / `start`；打不开时依次尝试 Chrome、Edge）；然后检查 BrowserSkill 扩展连接状态（执行 `bsk status` 看 browsers connected，或打开扩展弹窗确认 connected）。已连接 → 继续；未连接 → 先重连（重新打开浏览器、打开扩展弹窗，必要时重启 bsk daemon），最多重试 2 次；2 次重连都失败 → 写入 BROWSER_NOT_CONNECTED 结果并结束，不再执行后续步骤。
2. 打开 https://platform.deepseek.com/top_up，出现登录页 → LOGIN_REQUIRED。
3. 按上述金额与支付方式选择，点「去支付」；定位不到元素 → PAGE_CHANGED。
4. 二维码出现后截图保存到「二维码输出」路径。
5. 轮询支付结果（5s 间隔，最长 2 分钟）：出现"支付成功"文案、二维码消失或余额变化即视为成功；超时 → PAYMENT_TIMEOUT。
6. 打开 https://platform.deepseek.com/transactions，读取最新一笔充值的订单号与余额。

## 输出方式
写入「结果输出」路径（UTF-8 JSON）：
成功：{"ok":true,"orderId":"<订单号>","balanceAfter":"<余额>","message":"<可选备注>"}
失败：{"ok":false,"code":"<失败码>","error":"<具体原因>"}
失败码仅限：BROWSER_NOT_CONNECTED / BSK_CLI_MISSING / LOGIN_REQUIRED / PAYMENT_TIMEOUT / PAGE_CHANGED / UNKNOWN。
写完在本会话回复一句结果摘要即可，不复述本提示、不暴露路径与 QQ 号。
```

交换文件都在插件数据目录的 `recharge/` 子目录：

```
recharge/req-<id>.json  插件 → agent（充值请求：金额、方式、群、用户）
recharge/qr-<id>.png    agent → 插件（支付二维码，发送成功后删除）
recharge/res-<id>.json  agent → 插件（{"ok":true,"orderId":"…","balanceAfter":"…"}）
```

### 【4】怎么用

在群里（机器人需是群成员；发起人必须是**受信任成员**或白名单）：

```
@机器人 充值 50 支付宝
@机器人 充值 100 元 微信
```

流程：

1. 机器人回复「已受理充值 50 元（支付宝），正在生成支付二维码，请稍候……」；
2. 几秒后机器人把**支付二维码图片**发到群里；
3. 扫码付款（**2 分钟内**）；
4. 支付成功 → 机器人回执：

   > 充值成功：50 元（支付宝），订单号 `AB*****HIJ`，当前余额 120.35 元。

   **订单号中间 5 位固定用 `*` 替换**（如 `AB*****HIJ`），不会泄露完整单号；
5. 失败或超时 → 回执「充值失败：原因（编号 rcg-…）」。

规则与边界：

| 项目 | 说明 |
|---|---|
| 金额范围 | 1 ~ 50000 元；缺金额或支付方式时机器人会追问 |
| 支付方式 | 支付宝 / 微信支付（对应平台充值页的两个选项） |
| 超时（三段，合计最多 10 分钟） | ① 未出二维码：投递后 5 分钟强制中断（`E_QR_TIMEOUT`）；② 二维码已发出：重新计时 3 分钟等待支付；③ 3 分钟未到账：询问「继续 / 放弃」——继续再延长 2 分钟，放弃立即结束，2 分钟未回复按放弃处理。**二维码出现后 5 分钟规则不再生效** |
| 进度反馈 | 20s / 60s / 120s 三档推送「当前阶段 + 预计剩余时间」，最多 3 条；二维码发出后提示 2 分钟内支付 |
| 并发 | 同时支持多条请求，按请求编号区分 |
| 记录 | 请求写入 `state.json` 的 `recharge` 数组，最多保留 300 条 |
| 权限 | 仅受信任成员/白名单可触发（普通成员 @ 机器人不会进入充值流程） |

> **提示按实际情况区分（v1.15.3）**：
> - **完全未配置**（插件没有接入充值处理端）→ 配置引导：「充值失败，请先进行配置后再试，具体配置方法请参考帮助文档或联系 GitHub 仓库维护人员咨询」；
> - **已配置但失败** → 返回错误码 + 处置建议，不会复用上面的配置模板：
>
> | 错误码 | 含义 | 建议 |
> |---|---|---|
> | `E_AGENT_UNAVAILABLE` | 插件无法使用 DSH 的 agent 服务（少见） | 重启 DSH 后重试；若持续出现请查看 `recharge/bridge.log` |
> | `E_BROWSER_NOT_CONNECTED` | 浏览器扩展未连接 | 打开扩展确认「已连接」；必要时 `bsk daemon pair` 重新配对 |
> | `E_BSK_CLI_MISSING` | 找不到 bsk CLI | 按官方文档安装，或在 `cordis.patch.yml` 配置 `bskPath` 后重启 DSH |
> | `E_LOGIN_REQUIRED` | 模型平台未登录 | 在浏览器登录对应平台后重试 |
> | `E_PAGE_CHANGED` | 充值页结构变化，定位不到元素 | 联系维护者更新页面适配，或稍后重试 |
> | `E_PAYMENT_TIMEOUT` | 2 分钟内未检测到支付 | 订单已关闭，可重新发起充值 |
> | `E_QR_TIMEOUT` | 5 分钟内未生成支付二维码，任务已强制中断 | 检查浏览器扩展连接、平台登录状态与 `bsk status`，稍后重试 |
> | `E_HANDLER_TIMEOUT` | 处理端 3 分钟未返回结果 | 确认 DSH 与浏览器扩展在线后重试 |
> | `E_BUSY` | 同时进行的充值任务已达 3 个 | 等当前任务完成后再试 |
> | `E_QR_SEND_FAILED` | 二维码发送到群失败 | 确认机器人仍在群且未被禁言后重试 |
> | `E_UNKNOWN` | 其他未预期错误 | 稍后重试；持续失败请提供请求编号 |

### 【5】常见问题

| 现象 | 原因 / 解决 |
|---|---|
| 机器人回配置引导（「请先进行配置后再试」） | **完全没配置**处理端：DSH 里没装 BrowserSkill 插件，或宿主还没重启加载新版；按【3】配置 |
| 机器人回 `E_AGENT_UNAVAILABLE` | agents 服务不可用（少见）：重启 DSH 后重试；仍失败看 `recharge/bridge.log` |
| 机器人一直不发二维码 | 检查 `bsk status`、扩展是否 connected、浏览器是否登录；看数据目录 `recharge/` 下有没有 `req-*.json`（有=插件已受理，但 agent 没处理） |
| 提示“the bsk CLI ("bsk") was not found” | `bsk` 不在 PATH：按【3】的 AI 提示词让 AI 重新配置（它会以实际安装路径填 `bskPath`），或手动配置后重启 DSH |
| 提示“no browser is currently connected” | 浏览器扩展没装或没连接：装扩展、打开弹窗等 connected，必要时 `bsk daemon pair` 配对 |
| 二维码发不出 | 机器人被禁言/不是群成员（错误码 850018/40034101）；或图片超过 5MB（正常二维码不会） |
| 支付成功但没回执 | agent 没读到账单页：检查浏览器是否停在支付成功页；2 分钟后会回执失败，可重试 |
| 订单号显示 `*****` 太多 | 脱敏规则固定中间 5 位；单号本身很短时可能只剩星号 |

### 【6】安全说明

- 充值流程只在**本机**进行：请求文件、二维码、结果都写在插件数据目录，不上传第三方；
- agent 使用浏览器既有登录态，不接触账号密码，也不会把 Cookie/凭证写进日志；
- 支付二维码发在群里，所有群成员可见——如果不想公开，建议改成私聊触发（需要额外改造）；
- 建议只给**受信任成员**开放充值指令，并定期查看审计里的 `recharge-*` 记录。

## 8. 数据与安全

默认数据目录：

```text
~/.dsh/qqbot-guard/<profile>/<settingsNs>/
```

包含：

| 文件 | 内容 |
|---|---|
| `settings.json` | 凭据、违规规则、审批/欢迎/观察期/答题/公告/面板设置、按群覆盖 |
| `state.json` | 群注册表、成员台账、待审批、违规计数、黑名单、观察期、答题状态、统计 |
| `announcements.json` | 公告与发布结果 |
| `audit.jsonl` | 审计日志（超过 2 MB 自动轮转一次） |
| `security.json` | 面板密码的 PBKDF2 哈希（首次设置密码后生成） |

注意事项：

- NapCat 的 `token` 以明文保存在数据目录中，请限制目录权限，不要提交到 Git。
- 面板密码只保存 PBKDF2 哈希，不保存明文；首次访问时由部署方设置，源码不含默认密码。
- 独立面板默认监听 `0.0.0.0:8790`，使用 Cookie 会话 + CSRF 校验头 + 登录限流。
- 面板走 HTTP，**仅建议在可信局域网使用**；公网访问请套 HTTPS 反向代理或 VPN，并设置强密码。
- Web 写接口要求同源 + `x-qqbot-guard: 1` 请求头，降低 CSRF 风险。
- 所有对外接口返回统一信封：`{ ok, data, error, meta }`，`meta` 包含插件版本、生成时间、置信度。
- QQ API 连续失败会触发熔断，返回安全失败结果，不会把异常抛给宿主。
- 数据目录不可写时，插件会降级为内存模式；重启后设置和统计会丢失。

## 11. FAQ

**Q：机器人看不到群里的普通聊天？**  
A：v2.1.0 起只走 OneBot v11，普通 QQ 账号**能收到全量群消息**，不需要在 QQ 开放平台开通任何权限。收不到请检查协议端是否在线、机器人是否在群里。

**Q：公告为什么不是 QQ 原生群公告？**  
A：v2.1.0 起只走普通 QQ 账号。协议端在线且机器人为群管理员/群主时，公告可发成 **QQ 原生群公告**（`_send_group_notice`，支持置顶 / 需确认）；协议端离线或权限不足时自动回落为**普通群消息**，公告不会丢。面板「公告」页还可拉取/删除群内现有公告（`_get_group_notice` / `_del_group_notice`）。

**Q：收不到入群申请？**  
A：v2.1.0 起入群申请来自 OneBot 的 `request` 事件，不再需要 QQ 开放平台的 `GROUP_MEMBER_EVENT`。若收不到，依次检查：① 协议端在线且 WS 已连接；② 机器人是群管理员/群主（部分协议端只给管理员推送申请）；③ 面板「入群审批」是否只显示了已推送到的申请（OneBot 无主动拉取接口，见上文说明）。

**Q：禁言/移出失败？**  
A：机器人必须是群管理员，且不能操作群主/管理员/其他机器人。面板审计会显示官方错误码。

**Q：Windows 7 / 8.1 能用吗？**  
A：不能。dsh 要求 Node 24，而 Node 24 官方不支持 Windows 7/8.1。请升级系统或部署到 Linux 服务器。

**Q：iPhone 能安装吗？**  
A：不能作为宿主。把机器人部署在 Windows/Linux/macOS 或服务器上，然后用 iPhone Safari 打开独立控制台（`http://局域网IP:8790/`）或 dsh 面板。

**Q：独立控制台打不开？**  
A：确认插件已启动、8790 端口未被占用、系统和云服务器防火墙已放行；手机与电脑需在同一局域网。控制台「总览」页会列出所有可用地址。

**Q：忘记面板密码 / 想换密码？**  
A：最高管理员登录后在「设置 → 安全」中修改；两个密码都支持修改。若密码全部丢失，可停止 dsh，删除数据目录下的 `security.json`，重启后面板会回到“首次使用”页，重新设置密码即可。

**Q：为什么普通管理员修改某些设置要确认三次，还会在群里发通知？**  
A：这是为了约束协管/值班人员误改机器人级设置。只有普通管理员修改机器人设置时触发三次确认；最高管理员直接生效。改违规词、模糊别名、欢迎语不会触发。

**Q：普通管理员能改什么？**  
A：可以修改全部设置。违规词、模糊别名、欢迎语直接保存；机器人级设置（凭据、处罚、审批、观察期、答题、公告策略、按群覆盖等）需要连续确认 3 次。修改密码、导入配置、发布公告、入群审批、成员处置、群登记仍仅限最高管理员。

**Q：为什么不能直接填 QQ 号 @ 人？**  
A：v2.1.0 起成员标识就是真实 QQ 号，可以按 QQ 号查人。通知对象只填昵称即可：群内没有同名成员就会 @；有同名成员时从「成员列表」下拉选人，会自动填好昵称与 QQ 号。

**Q：为什么成员列表只有说过话的人？想看全部成员和 QQ 号怎么办？**  
A：v2.1.0 起只走 OneBot v11，在「设置 → NapCat 成员目录」里启用协议端后，插件通过 `get_group_member_list`（`no_cache: true`）就能直接拉到**全量成员与真实 QQ 号**。首次同步时若本地台账为空，会自动用协议端 `get_group_list` 的群补齐目标群（v2.2.6 修正）。协议端连不上时退回本地台账，此时只能看到发过言的成员。

**Q：NapCat 成员目录连不上 / 显示“未连接”？**  
A：依次检查：① 协议端已启动且开启 WebSocket 服务（NapCat 默认 `ws://127.0.0.1:3001`）；② 地址、端口、Token 与协议端配置一致；③ 点「测试连接」看具体报错；④ 协议端与 dsh 不在同一台机器时，把 `127.0.0.1` 换成可访问的 IP 并放行端口。连不上时插件会自动回退到本地台账，不影响其他功能。

**Q：入群答题怎么验证？**  
A：机器人会在新成员入群后直接在群里 @ 他提问，答对才发送欢迎语；超时或答错次数用尽会按配置警告/禁言/移出。需要机器人能收到群内普通消息。

**Q：Windows 精简版缺依赖怎么办？**  
A：先运行 `npm run doctor`。常见修复是补装 UCRT/VC++ 2015–2022 运行库，并确保 Winsock、DNS、防火墙出站 443 正常。

**Q：会不会调用 AI 模型、消耗 token？**  
A：默认不会。只有你在「设置 → AI 辅助审核」里主动开启，并选好 DSH 默认模型或填写 OpenAI 兼容接口后，才会在本地规则未命中时调用；随时可以关闭。模型失败会自动回退本地规则。普通用户通道同样遵循此开关：AI 未启用时只回固定提示，不会调用模型。
