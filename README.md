# dsh-qqbot-guard · QQ 群管家

> 只做群管理：违规防护、入群审批、入群欢迎、入群答题、观察期、公告发布与管理。  
> 不聊天、不发表情包、不生成图片/语音、不调用任何 AI 模型（仅按消息类型识别图片/卡片广告）。

- 当前版本：**v1.1.0**
- 本仓库默认分支：**`main`**
- 适用宿主：**dsh ≥ 0.2.0-rc.2**
- 运行时要求：**Node.js ≥ 24.9.0**（dsh 0.2.x 的硬性要求）
- 许可证：MIT

## 1. 这是什么

`dsh-qqbot-guard` 是一个运行在 **dsh（Node.js 宿主）** 里的 QQ 群管理插件。它只订阅群事件，做以下事情：

1. **群聊违规防护**：本地词表/正则/模糊变体/图片广告/链接/刷屏检测，命中后警告、禁言或移出。
2. **入群审批**：风险自动拒绝、关键词自动通过、黑名单自动拦截、面板手动审批。
3. **入群欢迎与观察期**：新成员欢迎语、默认 10 分钟观察期（可自定义）、可选入群答题。
4. **公告与群成员管理**：公告草稿/定时/立即发布/历史，群注册表、成员台账、禁言/解除/移出。
5. **独立局域网控制台**：不依赖 dsh 设置页，浏览器直接访问，双密码分权，支持按群覆盖、黑名单、审计导出、配置备份。

所有能力既可以在 dsh 内置设置页使用，也可以通过独立控制台 **`http://局域网IP:8790/`** 操作。

## 2. 与原版相比有哪些改动

### 2.1 定位差异

| 维度 | 原版 `dsh-qqbot` | 本版 `dsh-qqbot-guard` |
|---|---|---|
| 定位 | 综合 QQ 机器人（AI 对话 + 多种媒体能力 + 群管理） | 纯群管理工具 |
| AI 模型 | 有，依赖 AI 会话/模型调用 | **完全没有**，零模型调用 |
| 聊天回复 | 有 | 无 |
| 表情包 / 图片 / 语音 | 有相关模块与依赖 | 全部移除 |
| 群管理 | 有，但与 AI 会话深度耦合 | 保留并重写为独立事件驱动 |
| Web 面板 | 大型内置设置页 | 六页 dsh 面板 + **独立局域网控制台（双密码分权）** |
| 源码规模 | 约 910 个文件 / 15.47 MB（不含 node_modules） | **28 个核心文件 / 约 290 KB**（不含 README、LICENSE、package-lock） |
| 发布包 | 体积大，模块多 | **约 125 KB 的 zip**（含 README、LICENSE） |
| 原生模块 | 依赖链较重 | **零原生模块**，无需编译工具链 |
| 安装依赖 | 较重 | 仅 `@tencent-connect/qqbot-nodejs` + `@deepseek-ai/schemastery` |

### 2.2 明确移除的能力

- AI 对话、模型配置、提示词、会话上下文、长期记忆
- 表情包、图片生成/识别、语音/音频处理
- 与聊天相关的限流、人格、工具调用、多模态处理
- 原版中与群管理无关的重型依赖与前端大包

### 2.3 保留并重写的群管理能力

- 违规词、正则、可疑链接、刷屏检测
- 警告 / 禁言 / 移出，以及失败时的降级链
- 多次违规自动升级
- 入群申请自动/手动审批
- 入群欢迎与多变体模板
- 公告草稿、定时、立即发布、暂停、删除、历史
- 群注册表、成员台账、禁言/解除/移出
- 违规与操作审计

### 2.4 资源与稳定性优化

- **单一 WebSocket 连接**，不轮询业务事件
- **单个 30 秒公告调度器**，不为每条公告创建定时器
- 状态文件**合并写盘**（默认 5 秒），避免每条消息都写磁盘
- 成员、待审批、违规记录、审计日志都有硬上限
- 令牌缓存 + 并发单飞，避免重复取票
- QQ API 调用统一经过**熔断器**，连续失败快速降级
- 面板只在可见时低频刷新状态
- 无 AI 请求、无模型上下文，内存与 CPU 占用显著降低

## 3. 功能说明

### 3.1 违规防护

在「违规防护」页配置：

- 启用/关闭防护
- 命中动作：警告 / 禁言 / 移出群聊
- 禁言时长、同一用户冷却时间
- 违规词（每行一个）
- 正则规则（每行一个）
- 可疑链接检测与域名白名单
- 刷屏检测：时间窗口 + 消息条数
- 多次违规升级：第 N 次违规后执行更重动作
- 豁免群 openid

执行失败时会降级：**禁言失败 → 警告**，**移出失败 → 禁言 → 警告**；不会因为某个接口失败而抛异常中断。

### 3.2 入群审批

在「入群审批」页：

- 查看本地待审批列表
- 从官方接口同步待审批列表
- 手动通过 / 拒绝
- 命中风险提示自动拒绝
- 关键词自动通过
- 关键词自动拒绝

> 入群申请事件需要 QQ 开放平台授权 `GROUP_MEMBER_EVENT`，并在插件设置中开启「订阅入群申请事件」。

### 3.3 入群欢迎

- 模板变量：`{user}`（@新成员）、`{name}`（昵称）、`{group}`（群名）
- 支持多条欢迎语变体
- 变体选择由 **种子随机** 驱动：同群、同成员、同一天固定，可复现
- 修改「随机种子盐」即可换一批欢迎语

### 3.4 公告

- 新建公告：标题（可选）+ 正文
- 保存为草稿 / 定时发布 / 创建后立即发布
- 暂停定时、删除、查看发布历史
- 发布结果按群记录成功/失败
- 定时调度器每 30 秒扫描到期公告

> **重要限制**：QQ 官方机器人接口不提供“设置群公告”能力。本插件的公告是以**机器人消息**形式发送到目标群，不能替换 QQ 客户端里的原生群公告。面板中也有相同提示。

### 3.5 群与成员

- 群注册表：收到群事件后自动登记，也可手动添加群 openid + 名称
- 成员台账：记录机器人见过的成员（入群申请、群消息）
- 成员搜索：昵称 / openid
- 禁言 / 解除禁言 / 移出群聊

> QQ 官方暂未开放“全量成员列表”接口，因此成员台账只能覆盖机器人见过的成员。

### 3.6 独立局域网控制台（v1.1.0 新增）

插件启动后会自动拉起一个独立 HTTP 面板，默认监听 `0.0.0.0:8790`，不需要经过 dsh 设置页：

- 访问地址：`http://本机局域网IP:8790/`（控制台「总览」页会列出所有可用地址）
- **双密码分权**
  - **最高管理员**：可修改全部设置、凭据、审批、公告、成员操作、配置导入导出
  - **普通管理员**：只能修改违规词、模糊别名、入群欢迎语（模板与变体）
- **首次访问时由部署方设置密码**，插件不内置任何默认密码
- 密码要求：**8–64 位，必须同时包含字母和数字**；两个角色的密码不能相同
- 登录成功后使用 HttpOnly + SameSite=Strict 会话 Cookie；写请求必须带 CSRF 校验头
- 登录失败按 IP 限流，连续失败会临时锁定
- 支持按群覆盖、黑名单管理、审计筛选/CSV 导出、配置 JSON 导出/导入
- **修改日志**：查看设置保存、密码修改、配置导入记录，包含操作者、来源 IP 与变更摘要，支持关键字筛选和 CSV 导出
- 状态轮询只在页面可见时进行

> 首次打开控制台会进入“设置密码”页，由部署方自行填写最高管理员与普通管理员密码。密码只保存 PBKDF2 哈希，源码与仓库中不包含任何默认密码或明文。
>
> 首次设置入口对局域网开放：部署完成后请立即访问并设置密码，避免同一局域网内的其他人抢先初始化。
>
> 面板走 HTTP，适合可信局域网。不要把端口直接暴露到公网；如需远程访问，请使用 VPN 或带 HTTPS 的反向代理，并设置足够强的密码。

### 3.7 机器人设置的“三次确认 + 群内通知”

最高管理员在控制台修改**机器人级别设置**（连接凭据、处罚动作、审批策略、观察期、答题、公告策略、按群覆盖中的非词表字段等）时：

1. 前端连续弹出 **3 次确认**；
2. 服务端同时要求 3 次挑战令牌，缺少令牌会返回 `CONFIRM_REQUIRED`；
3. 保存成功后，异步向机器人已加入的**所有群**发送变更日志；
4. 在「设置 → 变更通知对象」里配置要 @ 的昵称或 openid（**由部署方自行设置，默认留空**）。留空时只发送变更日志，不 @ 任何人；openid 最可靠，昵称需要该成员在群里发过言才能匹配。

> “已加入的群”以插件登记的群为准（机器人收到过群事件或手动登记的群）。QQ 官方没有全量群列表接口；如果某个群从未产生事件，插件无法知道它。
> 成员必须先在群里发过言（进入成员台账）才能按昵称匹配到 openid；否则请直接填写 openid。

只修改违规词、模糊别名、欢迎语等“词”级别内容时，不触发三次确认和群通知。

### 3.8 v1.1.0 新增的群管理能力

- **管理员/信任成员豁免**：信任成员不触发警告/禁言/移出，同时允许使用群指令。由于 QQ 消息事件不提供成员角色字段，目前通过面板维护成员 openid 白名单（可从「群与成员」复制）。
- **违规累计黑名单**：窗口内第 N 次违规自动踢出并加入黑名单，重启后仍保留
- **模糊变体匹配**：识别拆字、空格、符号与常见谐音（如 `傻 b`、`shabi`），ASCII 短词带词边界，避免误伤普通英文
- **图片/卡片检测**：图片 + 广告关键词判定为广告；观察期内图片/链接可直接按观察期动作处理；卡片/名片消息可识别
- **群内管理员指令**：`/warn @成员 原因`、`/mute 10m @成员`、`/kick @成员`、`/rule`、`/help`
- **新成员观察期**：默认 **10 分钟**，可按群覆盖为任意分钟数（0 = 不启用）
- **入群答题**：入群后在群里提问，答对才通过；支持超时、最多答错次数、失败动作
- **按群独立配置**：每个群可单独覆盖违规动作、禁言时长、词表、观察期、欢迎语
- **配置导入/导出**：备份词表、按群配置、公告、黑名单；默认不导出 AppSecret

## 4. 兼容性

### 4.1 兼容矩阵

| 平台 | 结论 | 条件 / 说明 |
|---|---|---|
| Windows 10 / 11 x64 | 支持 | Node ≥ 24.9.0 + dsh |
| Windows Server 2016+ | 支持 | 同上 |
| Windows 10 LTSC / 精简版 | 有条件支持 | Node 与 dsh 能启动即可；不要移除 UCRT、Winsock、DNS、防火墙出站 443 |
| Windows arm64 | 有条件支持 | Node 24 对 Windows arm64 为 Tier 2 |
| Windows 7 / 8 / 8.1 | 不支持 | Node 24 官方不支持，dsh 无法启动 |
| Ubuntu 20.04+ / Debian 10+ / RHEL 8+ | 支持 | 内核 ≥ 4.18、glibc ≥ 2.28 |
| CentOS 7 / glibc < 2.28 | 不支持 | 官方 Node 24 二进制无法运行 |
| Alpine / musl | 有条件支持 | Node 官方列为 Experimental |
| macOS 13.5+ | 支持 | Node 24 要求 Darwin 22.6+ |
| iOS / iPadOS | 不能作为宿主 | 只能用 Safari 打开部署在电脑/服务器上的 dsh 面板 |
| Android / Termux | 实验性 | 可尝试，但不适合 24×7 运行，官方不支持 |

### 4.2 为什么有这些边界

1. **dsh 0.2.2 的 `engines` 要求 Node ≥ 24.9.0**，这是硬门槛。
2. Node 24 官方支持范围：
   - Windows 10 / Server 2016+（x64 为 Tier 1，arm64 为 Tier 2）
   - macOS 13.5+（Darwin 22.6+）
   - Linux 内核 ≥ 4.18、glibc ≥ 2.28
   - Alpine/musl 为 Experimental
3. **本插件零原生模块**，不需要 Python、VS Build Tools、node-gyp，也没有 `.node`/`.dll`/`.so` 文件。精简系统上常见的失败点是 Node 或 dsh 自带原生预编译包缺少 UCRT/VC++ 运行库，而不是本插件。

### 4.3 Windows 精简版建议

1. 不要移除 **UCRT、Winsock、DNS Client、防火墙出站 443**。
2. 如果 dsh 报原生模块加载失败，安装 **Microsoft Visual C++ 2015–2022 Redistributable (x64)**。
3. 数据目录不要放在 `Program Files`，默认在 `~/.dsh/qqbot-guard/...` 即可。
4. 部署后先运行 `npm run doctor`，红色必检项未解决前不要上线。
5. 控制台中文乱码不影响功能；可执行 `chcp 65001` 切到 UTF-8。

### 4.4 兼容性自检

插件启动时会自动检查：

- Node 版本
- 操作系统 / CPU 架构
- Windows UCRT
- Linux glibc / 内核
- macOS Darwin
- 全局 `fetch` / `AbortSignal.timeout`
- 数据目录可写
- dsh Web 服务是否就绪

手动运行完整体检：

```bash
npm run doctor
```

体检还会检查：

- QQ SDK 与配置 Schema 依赖能否加载
- 依赖里是否存在原生模块
- `bots.qq.com` 与 `api.bot.qq.com` 是否可达

面板「设置 → 兼容性自检」也会展示同样的结果。

> 测试边界：本版在 Windows 11 x64 + Node 26.10 上完成 40 项单测与交付自检；代码中没有平台专用分支，但未在真实 Linux/macOS 内核上运行自动化测试。建议在目标机器上运行 `npm run doctor` 和 `npm test`。

#### 没有 git 的机器

1. 下载仓库 ZIP：`https://github.com/XIAOzsdn/dsh-qqbot-guard/archive/refs/heads/main.zip`
2. 解压到任意目录（不要放在 `Program Files`）。
3. 把上面的 `git clone` 步骤替换为 `cd 解压后的目录`，其余命令不变。

#### 安装后配置

1. 打开 dsh Web → 设置 → **QQ 群管家**。
2. 在「设置」页填写：
   - AppID
   - AppSecret
   - 是否启动时自动连接
   - 是否订阅入群申请事件
3. 点击「保存并重连」。
4. 回到「总览」确认状态为 **在线**。
5. 在「违规防护」里按需调整违规词和动作。
6. 在「入群审批」里配置自动审批与欢迎语。
7. 在「公告」里创建第一条公告或草稿。

#### 升级

```bash
cd dsh-qqbot-guard
git pull
npm install
npm test
dsh plugin --profile web add "$PWD"
# 重启 dsh web
```

数据目录独立于源码，升级不会清空设置和公告。

#### 卸载

```bash
dsh plugin --profile web remove dsh-qqbot-guard
```

> 不同 dsh 版本的插件管理命令可能略有差异；如果你的版本不支持 `remove`，请在 dsh 的插件管理入口中卸载。

如需彻底清理数据，再删除数据目录（默认 `~/.dsh/qqbot-guard/`）。

### 5.4 打开独立控制台

1. 启动 dsh（插件会自动监听 `0.0.0.0:8790`）。
2. 在电脑/手机浏览器打开 `http://<运行 dsh 的机器局域网 IP>:8790/`。
3. 首次访问会进入“设置密码”页：分别设置最高管理员密码与普通管理员密码（8–64 位，必须同时包含字母和数字，两个密码不能相同）。
4. 保存后会自动以最高管理员身份登录；之后可在「设置 → 安全」中修改密码。
5. 如果打不开：检查 8790 端口占用、系统防火墙、云服务器安全组，确认设备在同一局域网。

> 不推荐直接把 8790 暴露到公网。远程使用请走 VPN 或 HTTPS 反向代理。

## 6. QQ 开放平台权限

在 [QQ 开放平台](https://q.qq.com/) 创建/配置机器人时，至少确认：

- 机器人已发布到目标群，并被设为**群管理员**
- 开通群管理相关能力：入群审批、禁言、移除成员
- 开通「群聊全量消息」（否则只能收到 @ 机器人的消息）
- 开通 `GROUP_MEMBER_EVENT`（否则收不到入群申请）
- 如需 Markdown 警告/欢迎语，开通 Markdown 能力；未开通时插件会自动降级为纯文本

常见错误码会显示在面板审计记录中，例如：

- `11703`：没有接口权限 / 不是群管理员
- `40103004`：不能操作该成员（群主/管理员/机器人）
- `40103011`：机器人关闭了移除成员权限
- `304036`：Markdown 未授权（已自动降级纯文本）

## 7. 数据与安全

默认数据目录：

```text
~/.dsh/qqbot-guard/<profile>/<settingsNs>/
```

包含：

| 文件 | 内容 |
|---|---|
| `settings.json` | 凭据、违规规则、审批/欢迎/观察期/答题/公告/面板设置、按群覆盖 |
| `state.json` | 群注册表、成员台账、待审批、违规计数、黑名单、观察期、答题状态、统计 |
| `announcements.json` | 公告与发布结果 |
| `audit.jsonl` | 审计日志（超过 2 MB 自动轮转一次） |
| `security.json` | 面板密码的 PBKDF2 哈希（首次设置密码后生成） |

注意事项：

- AppSecret 以明文保存在数据目录中，请限制目录权限，不要提交到 Git。
- 面板密码只保存 PBKDF2 哈希，不保存明文；首次访问时由部署方设置，源码不含默认密码。
- 独立面板默认监听 `0.0.0.0:8790`，使用 Cookie 会话 + CSRF 校验头 + 登录限流。
- 面板走 HTTP，**仅建议在可信局域网使用**；公网访问请套 HTTPS 反向代理或 VPN，并设置强密码。
- Web 写接口要求同源 + `x-qqbot-guard: 1` 请求头，降低 CSRF 风险。
- 所有对外接口返回统一信封：`{ ok, data, error, meta }`，`meta` 包含插件版本、生成时间、置信度。
- QQ API 连续失败会触发熔断，返回安全失败结果，不会把异常抛给宿主。
- 数据目录不可写时，插件会降级为内存模式；重启后设置和统计会丢失。

## 10. FAQ

**Q：机器人看不到群里的普通聊天？**  
A：需要在 QQ 开放平台开通「群聊全量消息」。否则机器人只能收到 @ 它的消息。

**Q：公告为什么不是 QQ 原生群公告？**  
A：QQ 官方机器人接口没有设置群公告的能力。本插件发送的是机器人消息，支持定时与历史管理。

**Q：收不到入群申请？**  
A：检查是否开通 `GROUP_MEMBER_EVENT`，以及插件设置里是否开启「订阅入群申请事件」。

**Q：禁言/移出失败？**  
A：机器人必须是群管理员，且不能操作群主/管理员/其他机器人。面板审计会显示官方错误码。

**Q：Windows 7 / 8.1 能用吗？**  
A：不能。dsh 要求 Node 24，而 Node 24 官方不支持 Windows 7/8.1。请升级系统或部署到 Linux 服务器。

**Q：iPhone 能安装吗？**  
A：不能作为宿主。把机器人部署在 Windows/Linux/macOS 或服务器上，然后用 iPhone Safari 打开独立控制台（`http://局域网IP:8790/`）或 dsh 面板。

**Q：独立控制台打不开？**  
A：确认插件已启动、8790 端口未被占用、系统和云服务器防火墙已放行；手机与电脑需在同一局域网。控制台「总览」页会列出所有可用地址。

**Q：忘记面板密码 / 想换密码？**  
A：最高管理员登录后在「设置 → 安全」中修改；两个密码都支持修改。若密码全部丢失，可停止 dsh，删除数据目录下的 `security.json`，重启后面板会回到“首次使用”页，重新设置密码即可。

**Q：为什么修改某些设置要确认三次，还会在群里发通知？**  
A：这是为了避免误改机器人级设置。只有最高管理员修改机器人设置时触发；改违规词、模糊别名、欢迎语不会触发。

**Q：普通管理员为什么改不了处罚动作？**  
A：普通管理员按设计只能改“词”：违规词、模糊别名、入群欢迎模板/变体。凭据、处罚、审批、观察期、答题、公告等都需要最高管理员。

**Q：入群答题怎么验证？**  
A：机器人会在新成员入群后直接在群里 @ 他提问，答对才发送欢迎语；超时或答错次数用尽会按配置警告/禁言/移出。需要机器人能收到群内普通消息。

**Q：Windows 精简版缺依赖怎么办？**  
A：先运行 `npm run doctor`。常见修复是补装 UCRT/VC++ 2015–2022 运行库，并确保 Winsock、DNS、防火墙出站 443 正常。

**Q：会不会调用 AI 模型、消耗 token？**  
A：不会。本插件没有任何模型调用、会话或提示词逻辑。
